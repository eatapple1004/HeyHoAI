## 0. 한 줄 임무
현재 54개 템플릿이 **각각 정확히 어떤 사진/영상을 만드는지 확정**하고, **무엇을 빼고/합치고/추가**할지 정해 **카탈로그별 최종 세트(v2) + 엔진용 레시피**를 산출하라.

## 1. 프로젝트 30초 브리핑
Doppia(=doppia.ai) = **AI 마케팅 콘텐츠 생성 SaaS.** 유저가 **얼굴 셀카(인플루언서) 또는 제품 사진(브랜드) 1장**을 올리고 **템플릿(양식)만 고르면** AI가 마케팅용 **사진·릴스(짧은영상)·UGC 광고**를 자동 생성. **핵심 철학 = "프롬프트 0 / 노스킬"** — 유저는 글을 쓰지 않고 양식만 고른다. 사용량은 **크레딧(◈)** 차감.

## 3. 레시피 스키마 (엔진이 먹는 형식 — 반드시 준수)
통합 스키마 v1 = **A2 레이어(look) + A5 샷리스트(shots)**. 한 템플릿 = 객체:
```
{ mode, category, name, output_type:'image_set'|'reel', credit_cost, rationale,
  config:{
    output:{type, count, aspect_ratio},               // 사진 count=4(4:5), 릴스 count=샷수(9:16)
    subject:{type:'face'|'product'|'avatar', reference_strategy:'identity_lock'(얼굴)|'product_composite'(제품), min_refs:1},
    look:{style_preset, attributes:['lighting:..','color:..','texture:..','context:..'], wardrobe?(얼굴만), extra_positive, negative},
    shot_strategy:'list',
    shots:[{scene, pose, composition:'closeup'|'medium_shot'|'full_body'}],   // 제품모드 pose=제품 앵글
    reel?:{per_shot_motion:[샷별], duration_per_shot, transition, music_mood, captions},  // 릴스만
    editable_slots?:[], provider:{image:'nano-banana', video:'kling'}
  } }
```
- **비용 규칙(문서 기준)**: image_set = count×0.5, reel = shots×2, on-model 착용(on_model_tryon) +1. (예: 4장=◈2, 3샷릴스=◈6, 온모델 4장=◈5)
- **프롬프트 품질 바**: 구체적 라이팅/렌즈/씬/무드/구도 + 실효성 있는 `negative`. 얼굴=identity_lock, 제품=product_composite.
- **⚠️ 엔진 버그(꼭 인지)**: `src/images/imagePrompt.builder.js`의 전역 SAFETY_NEGATIVE가 **모든 렌더에 'text','logo' 주입** → 글자/브랜드 들어가는 템플릿(스펙 그리드·메뉴판) 파괴. 해결안 = 템플릿별 negative 분리 + 글자는 오버레이. 발굴/강화 시 이 한계 반영.

## 4. 이미 정해진 것 (제약·원칙 — 바꾸지 말 것)
- **노스킬 철학**: 유저는 프롬프트 안 씀. 템플릿은 "고르기만" 하면 되는 완성형.
- **마켓 전략 = 하이브리드, 출시 1차 = 공식 템플릿으로 카탈로그를 채움**(유저 발행·판매는 2차). 즉 **이 54개(→v2)가 출시 카탈로그의 본체.**
- **두 모드**: 얼굴(인플루언서/UGC) · 제품(7버티컬). 엔진은 공유.
- **출력 2종**: 사진세트 / 릴스. 스키마 v1 준수.

## 5. 미션 상세 — ①발굴 ②선별 ③강화

### ① 발굴 (Discover)
카탈로그별로 **후보 포맷을 폭넓게 발굴**:
- **2026 트렌드·플랫폼**(IG Reels/TikTok/Shorts)에서 실제로 잘 되는 포맷 (예: ASMR, GRWM, 360, before/after, POV, day-in-life, "tiktok made me buy it", talking-pet 등).
- **구매 JTBD(jobs-to-be-done)** 기준 빠진 전환 프레임 (예: 사이즈/핏 온바디, before/after, 스케일/치수, 제품 들고 사용, 메뉴판/정보 프레임, 정적 UGC 광고).
- 경쟁/레퍼런스(쇼핑몰·DTC·크리에이터)에서 표준 컷 유형.
- 산출: 카탈로그별 후보 목록(이름 + 무엇을/왜 + 사진/영상 + 예상 비용).

### ② 선별 (Select)
각 카탈로그를 **응집된 세트(기본 6, 필요시 5~8)** 로 확정. 기준 4축:
- **커버리지**: 해당 버티컬의 핵심 상업 컷을 다 덮나? 중복(near-duplicate) 없나?
- **트렌드 적합**: 2026 플랫폼에서 통하나? 구식 컷 제거.
- **원가-가치**: 비용이 제작부하·가치와 맞나? 카탈로그마다 싼 진입(◈2)이 있나?
- **AI 난이도**: 현재 모델로 실현 가능한가? (손가락·글자·말하는입·360 온모델 = 위험 → 범위 제한 or 제외)
- 산출: 카탈로그별 **keep / cut / merge / add** 결정표(+ 한 줄 이유).

### ③ 강화 (Enhance)
남기거나 추가하는 **모든 템플릿에 대해**:
- **정확한 산출물 정의**: "이 템플릿은 [무슨 종류의] 사진/영상을 [몇 컷] 만든다 — 각 컷은 [씬/구도/무드]"를 명확히. (사람이 결과를 예측 가능하게.)
- **스키마대로 레시피 작성**: §3 형식, 구체 프롬프트 + negative + 샷리스트(+릴스 모션). 비용 규칙 준수.
- AI 위험 템플릿은 메타에 'experimental / 사람검수' 표시 + 범위 제한(예: 손가락은 부분 크롭).

## 6. ★ 최적화 진단 요약 (이미 도출됨 — 이걸 검증·실행하라)
전체 결론: **"포맷은 풍부하나 전환 JTBD가 빈다(최적 아님)."** 카탈로그 점수: home·tech 7 / fashion·beauty·pet 6.5 / influencer·jewelry 6 / **food 4.5 · ugc 4(최약).**
핵심 권고(요지):
- **추가(전환 포맷)**: 정적 UGC 포토광고(◈2, 최고 레버리지) · 'TikTok made me buy it' POV · 패션 핏/사이즈 온바디 + 아웃핏 전환 릴스 · 뷰티 before/after · 인플루언서 제품-들고 Haul + day-in-life · 주얼리 스케일/사이징 · 테크 in-hand 데모 · 푸드 메뉴판 + 서빙/테이블.
- **삭제/병합**: 인플루언서 Trending Lip-Sync(구식+음원권리) · UGC Street Interview(AI 신뢰↓) · 패션 Editorial Lookbook↔On-Model Studio · 주얼리 무광 정물 3개→1 · 푸드 360 Glaze↔Sizzle · 홈 ◈2 4개 중복 · 뷰티 ASMR Unbox↔GRWM Routine.
- **리프라이스**: 온모델 사진 ◈6→◈5 · UGC 평면 ◈8 → 1~2샷 ◈4/3샷 ◈6/4샷 ◈8 + ◈2 정적 진입 · 큰 릴스 정합 · **1~2샷 싼 릴스 티어 신설**(가장 싼 영상이 ◈6 바닥인 문제).
- **구조/엔진**: 전역 text/logo 네거티브 템플릿별 분리(스펙·메뉴), 손가락/립싱크/360 negative 강화 + 사람검수 플래그, `parent_id`/`editable_slots`로 근접중복을 변형으로 흡수.
→ **새 세션은 이 권고를 맹신 말고 검증한 뒤 카탈로그별 최종안으로 확정·구현.**

## 7. 산출물 (Deliverables)
1. **카탈로그별 최종 결정표** (keep/cut/merge/add + 이유 + 최종 6±목록).
2. **각 템플릿 산출물 스펙** (무슨 사진/영상 만드는지, 한국어 + 영어).
3. **v2 레시피 시드** — `src/recipes/seeds/recipes.<catalog>.v2.js` (또는 기존 갱신), §3 스키마 준수.
4. **갱신된 한눈에/한국어 카탈로그** (`public/_overview.html`, `docs/템플릿_한국어_카탈로그.md` 동기화).
5. 변경 요약 + AI 위험·엔진 의존(text 오버레이 등) 메모.
- 형식: 영어 프롬프트(엔진용) + 한국어 설명(사람용) 2벌. 비용 규칙·노스킬 준수.

## 8. 추천 작업 방식 (선택)
- 카탈로그 9개를 **병렬**로(발굴→선별→강화) 처리 후, 교차 일관성(가격사다리·중복·트렌드) 동기화 패스. (멀티에이전트 워크플로 가능 — 사용자가 "ultracode"/워크플로 허용 시.)
- 엔진 미연결이라 실렌더 검증은 불가 → **프롬프트·샷리스트로 산출물 명세를 확정**(추후 엔진 연결 시 실렌더로 미세조정).
