## 1. 라이프사이클 (2축)

```
status:      held ──(테스트)──▶ testing ──(통과)──▶ confirmed ──▶ 출시 가능
provisional: (별개 축) 18개 = 로스터 미승인. confirmed 되려면 status=confirmed AND provisional 해제 둘 다.
```
- **held(보류)** = 기본값. 현재 93/93. 출시 안 함.
- **testing(테스트중)** = 검수 진행 중.
- **confirmed(확정)** = 테스트 통과 → 출시 가능.
- **출시 = confirmed만.** 현재 confirmed 0 → **출시 0.**

## 3. "테스트"의 정의 — 단계별 (⚠ 현재 mock)
현재 **엔진 미연결(mock 단계)이라 실렌더 불가.** 그래서 테스트는 2단계:

| 단계 | 가능 시점 | 테스트 내용 | 확정 근거 |
|---|---|---|---|
| **A. 스펙 QA** | **지금 가능** | 프롬프트·샷리스트·negative·비용·가드·🅣/⚠ 플래그를 1:1로 읽고 검증. 노스킬 예측가능성 확인. | 스펙 합격 → `testing` |
| **B. 실렌더 QA** | 엔진 연결 후 | 실제 출력 N장 렌더 → 눈으로 품질·수율·정체성·손/글자/모핑 확인, 측정. | 렌더 합격 → `confirmed` |

→ **지금은 A(스펙 QA)까지만 확정 가능**, B(실렌더)는 엔진 착지 후. 또는 A를 "잠정 confirmed"로 두고 B에서 최종 확정하는 2-게이트도 가능(사용자 선택).
