# 로컬 검증·올리기 가이드 (모든 템플릿 생성기 워커 공용)

> **목적**: 시드(`recipes.<key>.v2.js`)를 고친 뒤 **로컬에서 검증·studio 노출**까지 가장 빠르게. 매번 파이프라인을 역설계하지 말 것.
> **출처**: home v2 형제 20종 로컬 테스트(2026-06-14) 시행착오 + jewelry v2 검증 + 스크립트 정독. 작성 2026-06-14.
> **결론 먼저**: jewelry에도 별도 비법은 없다 — 전 섹션이 **같은 3스크립트 체인**을 쓴다. 아래가 그 정식 경로 + 시간절약 지름길이다.

## ⚡ TL;DR — 검증 깊이별 3단계 (필요한 만큼만)

| 목적 | 명령 | DB/인증/서버 | 소요 |
|---|---|---|---|
| **A. 프롬프트만 확인** | `node src/recipes/resolve.demo.js` | ❌ 불필요 | 초 |
| **B. 시드 검증 + 카드 데이터 확인** | 3스크립트 체인 + 헤드리스 조회 | ❌ 불필요 | 초 |
| **C. 브라우저 studio 눈으로** | B + 서버 + 로그인 | ✅ 필요 | 분 |

**대부분의 검증은 A·B로 끝난다.** C(브라우저)는 "실제 카드 UI를 봐야 할 때"만. ← home 워커가 이걸 몰라 곧장 C로 가서 인증벽·포트충돌로 오래 걸렸다.

## 0) 시드 구조 (실측 — 정확)

`credit_cost`는 **숫자**(객체 아님). `config.output`은 객체.

```js
{
  mode:"product", vertical:"home", category:"Scene",
  name:"Room & Warmth Styled",          // 전역 고유 → id = slug(name)
  output_type:"image_set",              // 'image_set' | 'reel'
  credit_cost:3,                        // 숫자
  rationale:"...",
  meta:{ ... },
  config:{
    schema_version:1, mode:"product",
    output:{ type:"image_set", count:6, aspect_ratio:"4:5" },
    subject:{ type:"product", reference_strategy:"product_composite", min_refs:1 },
    look:{ style_preset:"Interior", attributes:[...], extra_positive:"...", extra_negative:"..." },
    shot_strategy:"list",
    shots:[ { scene, pose, composition } ],   // count개 == output.count
    reel:{ per_shot_motion:[], duration_per_shot, transition, music_mood, captions },  // reel만
    provider:{ image:"nano-banana", video:"kling" }
  }
}
```
- **비용공식**: image `credit_cost = round(count×0.5)` 이상 · reel `= shots×2`(엄격) · 온모델 +1.
- **네거티브는 `look.extra_negative`** (엔진이 읽는 live 필드). `look.negative`는 死필드 — 쓰지 말 것. `text`/`watermark`/`logo`는 전역 SAFETY가 자동 주입하니 넣지 말 것.
- **🅣 글자 오버레이**: `text_overlay:true` + 그 템플릿 `extra_negative`에서 text/logo 제외 + `meta.render_notes`.

## A) 프롬프트만 확인 — 가장 빠름, DB·인증·서버 0

```bash
cd ~/HeyHoAI
node src/recipes/resolve.demo.js          # 데모 presetMap/attributeMap로 프롬프트 출력
```
- 새 레시피를 데모에 넣어보려면 `resolve.demo.js`가 import하는 시드를 바꾸거나, 아래처럼 직접:
```bash
node -e 'const{resolveRecipe}=require("./src/recipes/recipeResolver");const r=require("./src/recipes/seeds/recipes.home.v2.js").find(x=>x.name==="Twilight Corner Glow");console.log(resolveRecipe(r.config,{subject:{type:"product",name:"vase"},presetMap:{},attributeMap:{},userSlots:{}}).jobs[0].prompt)'
```
→ `resolveRecipe`는 **순수 함수(DB 무관)**. 프롬프트 정합성은 이걸로 끝.

## B) 시드 검증 + 카드 데이터 확인 — DB·인증·서버 0

### B-1. 3스크립트 체인 (순서 고정 — drift-guard 때문에 셋 다, 순서대로)
```bash
node scripts/consolidate_recipes.js     # → _STATUS.md, _CATALOG.json (로딩·스키마·비용·6~8·중복이름)
node scripts/recipe_card_contract.js    # → _card_contract.proposed.json (id=slug, drift-guard)
node scripts/export_recipe_cards.js     # → public/js/recipes.generated.js (studio 카드그리드)
```
콘솔에서 내 섹션 `OK` + `중복 이름 없음` + `drift-guard OK` 확인.

### B-2. 카드 데이터 헤드리스 조회 (브라우저 없이 카드 노출 확인)
```bash
node -e 'const s=require("./src/recipes/recipeStore");const h=s.list({vertical:"home"});console.log(h.length, h.map(r=>r.name).join(" | "))'
```
→ recipeStore가 시드를 읽어 카드 목록을 그대로 보여줌. **인증·서버 없이** "내 템플릿이 카드로 잡히나" 확인 가능.

## C) 브라우저 studio 눈으로 — 서버 + 로그인 필요

### C-1. 서버는 **하나만** (포트충돌 주의)
- preview 도구로: `preview_start("heyhoai")` (launch.json, npm run dev, :3000).
- **수동 `npm start`와 preview_start를 동시에 쓰지 말 것** → 3000 충돌. 하나만.

### C-2. 인증 — studio는 `/saas-login`으로 리다이렉트됨 (saas-auth.js)
가장 빠른 통과 = **브라우저 콘솔에서 직접 로그인 fetch** (폼 클릭보다 확실):
```js
await fetch('/api/auth/login',{method:'POST',headers:{'Content-Type':'application/json'},
  body:JSON.stringify({email:'sibtest@local.test',password:'Test1234!'})})
```
- 로컬 테스트 계정 **이미 존재**: `sibtest@local.test` / `Test1234!`. 없으면 `/api/auth/signup` 동일 바디로 생성.
- 로그인 후 `location.href='/studio'`.

### C-3. studio 필터 — `?vertical=home`은 그리드에 안 먹음
카드는 **mode=shopping + 버티컬 필터**에 있다. 콘솔에서 직접:
```js
setMode('shopping','Home')   // 'Jewelry' 등. 첫 글자 대문자. → 그리드 렌더
```
(제품 섹션=shopping 모드. influencer/headshot/general=influencer 모드. ugc=ugc 모드.)
- 캡처가 잘리면 뷰포트를 길게(예 1500×2200) 리사이즈.

## ⚠️ 함정 모음 (실제로 시간 잡아먹은 것들)

| 함정 | 증상 | 회피 |
|---|---|---|
| 곧장 브라우저로 직행 | 인증벽·포트충돌로 지연 | 먼저 A·B로 검증, C는 최후 |
| `?vertical=home` 신뢰 | 기본 influencer 모드만 뜸 | `setMode('shopping','Home')` |
| 서버 2개 | EADDRINUSE 3000 | 서버 하나만(preview 또는 수동) |
| 3스크립트 일부만 실행 | drift-guard exit(1) | 셋 다 순서대로 |
| 6~8 초과 추가 | consolidate `draft` 표기 | 로컬 실험은 OK, **정식 확정 전 6~8로** |
| `look.negative`에 작성 | 엔진에 안 닿음(死필드) | `look.extra_negative` 사용 |
| text/logo 네거티브 | SAFETY와 이중주입 | 넣지 말 것(🅣만 예외 처리) |
| resolve가 DB 필요 | studio resolve 시 styleRepo/visualRepo 쿼리 | 프롬프트만이면 `resolve.demo.js`(DB 무관) |
