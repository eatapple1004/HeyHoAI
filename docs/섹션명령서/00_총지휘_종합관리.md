# 총지휘 세션 — 12개 섹션 종합·관리 명령서

> 너는 **총지휘(orchestrator) 세션**이다. 12개 섹션 워커 세션이 각각 만든 템플릿을 **수거·검증·종합·관리**한다.
> 작업 디렉터리 `~/HeyHoAI`, 브랜치 `feat/ux-monetization-v2`. 세션끼리 메모리는 공유 안 되므로 **공유 백본 = 레포 파일시스템.**

## 1) 구조 (어떻게 묶이나)
- **워커 세션 12개**: 각자 `docs/섹션명령서/<NN_key>.md` 1개를 받아 그 섹션 템플릿을 만들고 → **`src/recipes/seeds/recipes.<key>.v2.js`** 에 떨군다. (key: influencer·fashion·beauty·jewelry·food·coffee·home·tech·pet·ugc·general·headshot)
- **총지휘(너)**: 워커가 떨군 시드들을 **한 스크립트로 수거·검증**하고 현황을 관리, 이슈를 워커에 피드백, 전부 끝나면 최종 머지.

## 2) 핵심 도구 — 종합 스크립트 (이거 하나면 됨)
```
node scripts/consolidate_recipes.js
```
- 11개 섹션의 `recipes.<key>.v2.js` 를 자동 스캔(워커가 수동 보고 안 해도 됨).
- 검증: 로딩 가능 · 스키마 필수필드 · **비용공식(릴스=shots×2 엄격, 사진=count×0.5 이상)** · **섹션 내/전체 중복 이름** · 가격사다리(◈2 진입·싼 릴스 ≤◈4) · 개수(6~8).
- 산출: 콘솔 대시보드 + **`docs/섹션명령서/_STATUS.md`(현황표·이슈)** + `_CATALOG.json`(통합 데이터). exit 0=클린, 1=이슈있음.
- **워커가 한 섹션 끝낼 때마다 재실행** → `_STATUS.md`로 진행률·이슈 즉시 파악.

## 3) 관리 루틴
1. 주기적으로 `node scripts/consolidate_recipes.js` 실행 → `_STATUS.md` 확인.
2. **이슈 있는 섹션** → 해당 워커 세션에 피드백(아래 4).
3. **전체 중복 이름** → 한쪽 리네임 지시. 섹션 간 템플릿 이름은 **고유**해야 함. ✅ *해소(2026-06-10): `Unbox ASMR Reel` 충돌 → jewelry는 `Jewelry Unbox ASMR`로 개명, tech는 `Tech Unbox ASMR`로 개명. 현재 중복 0.*
4. 가격사다리 갭 → 보강 요청. **단 의도된 예외는 승인 처리.** ✅ *갱신(2026-06-10): jewelry 싼 릴스 "의도적 미보유"는 더 이상 예외 아님 — `Sparkle Snap` 🎬1·◈2 추가로 공백 해소, 이제 **11섹션 전부 ≤◈4 릴스 보유**.*
5. **신규 2개(general·headshot)** 가 `pending(없음)`인 한 미완 — 워커 착수 확인.
6. **로컬 검증 절차 공통화**: 워커가 "로컬 어떻게 올리지?"로 헤매지 않게 → **[_로컬검증_가이드.md](_로컬검증_가이드.md)** 안내(프롬프트=`resolve.demo.js`, 카드=3스크립트+`recipeStore.list`, UI=서버 하나+콘솔 로그인+`setMode('shopping','<Vertical>')`). 브라우저 직행은 인증벽·포트충돌로 느림.

## 4) 세션 간 소통 (옵션 — backbone은 파일)
파일시스템이 1차. 실시간 조율이 필요하면 세션관리 MCP 사용:
- `mcp__ccd_session_mgmt__list_sessions` — 돌고 있는 워커 세션 목록.
- `mcp__ccd_session_mgmt__send_message` — 특정 워커 세션에 피드백/지시 전달(예: "tech: Unbox 이름 충돌 → 리네임").
- `mcp__ccd_session_mgmt__search_session_transcripts` — 특정 산출/결정 검색.
(없어도 됨: 워커가 시드만 떨구면 너는 스크립트로 수거 가능.)

## 5) 충돌·정합 규칙
- **중복 이름**: 전체에서 고유. 충돌 시 섹션 접두.
- **교차 카탈로그 중복 포맷**(예: 여러 섹션의 'Unbox ASMR') — 허용하되 **이름·프롬프트는 섹션 특화**로 차별. 완전 동일 중복이면 한쪽 제거.
- **스키마**: `recipes.influencer.v2.js` 형식 = module.exports 배열, 각 객체 §스키마(아래) 준수.
- **비용**: 릴스 ◈=shots×2 엄격. 사진은 count×0.5 이상(온모델/착용 프리미엄 ◈5 허용).
- **가격사다리**: 섹션마다 ◈2 사진 진입 + 싼 릴스(≤◈4) 1개(의도적 예외는 명시).

## 7) 워커에게 주는 산출 규약 (각 섹션 브리프에도 동일 명시)
1. 파일: `src/recipes/seeds/recipes.<key>.v2.js`, `module.exports = [ ...레시피 ]`.
2. 스키마(§): `{ mode, category, name(전체고유), output_type:'image_set'|'reel', credit_cost, rationale, config:{ output{type,count,aspect_ratio}, subject{type,reference_strategy,min_refs}, look{style_preset,attributes[],wardrobe?,extra_positive,negative}, shot_strategy:'list', shots[{scene,pose,composition}], reel?{per_shot_motion[],duration_per_shot,transition,music_mood,captions}, provider{image,video} } }`
3. 비용: 릴스=shots×2, 사진=count×0.5(온모델 +프리미엄). 섹션당 6~8개, ◈2 진입+싼 릴스.
4. 플래그: AI 위험 = `meta.flags:['experimental','needs_human_review']`, 글자 의존 = `config.text_overlay:true`(+ 그 템플릿 negative에서 'text','logo' 제외).
5. 끝내면 끝 — 총지휘가 `consolidate_recipes.js`로 수거. (별도 보고 불필요, 단 이름 충돌만 피할 것.)
6. **작업 기록 루틴 (필수 · 작업마다 즉시)** — 시드를 만들거나 고치면 끝나는 즉시:
   - **(a)** `node scripts/consolidate_recipes.js` 재실행 → `_STATUS.md`·`_CATALOG.json` 자동 갱신(개수·이슈·중복).
   - **(b)** 사람용 **백본 문서**의 해당 섹션을 시드와 동기화 — `docs/템플릿_v2_발굴선별강화_결과.md`(개수·결정표·번호표·가격사다리) · `docs/템플릿_한국어_카탈로그.md` · `public/_overview.html`. (시드는 자동수거되지만 **이 3개 문서는 수동 동기화**라 안 하면 drift 발생 — 실제 사례: 패션 시드 8개 ↔ 결과.md 7개 불일치를 사후 수정함.)
   - **(c)** 발굴·선별·갭분석 등 **판단 산출물**은 휘발 채팅/`/tmp`에만 두지 말고 관련 docs에 남긴다(필요 시 신규 `docs/<key>_*.md`).
   - 목적: 총지휘·다른 세션이 시드를 직접 안 봐도 **어느 백본 문서에서든 현재 상태를 drift 없이** 읽게.
