# 결제 취소(환불) 구현 — 2026-09-09

PortOne 실운영모드 승인(2026-09-09 메일)에 따른 필수 요건 **"실운영 전환 후 결제 및 환불 테스트 진행"** 대응.
그 전까지 우리 코드에는 **취소 API가 한 줄도 없었다** — 콘솔에서 수동 취소는 되지만 크레딧이 회수되지 않아
"돈은 돌려주고 재화는 남는" 상태가 됐다. 그 구멍을 메운 작업이다.

관련: `public/refund.html`(규정 원문) · `docs/결제_현황.md` · 메모리 `payment-status`

---

## 1. API

모두 Nest 소유(`/api/billing`·`/api/admin/refunds` — `NEST_PREFIXES`에 등재).

### 사용자 (JwtAuthGuard)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/billing/portone/orders?limit=` | 내 PortOne 결제 내역 + 취소 누적액 |
| GET | `/api/billing/portone/refund/:paymentId` | **환불 가능 여부 미리보기**(부작용 없음). 소유자만 — 남의 결제번호는 403 |
| POST | `/api/billing/portone/refund` `{paymentId, reason?}` | 셀프 **전액** 환불 |

셀프 환불은 규정상 **미사용 + 7일 이내 + 전액**만 열린다. 어긋나면 400과 함께 `blockers[0]` 사유를
그대로 돌려주고 고객센터로 안내한다(부분사용분은 "회사 귀책이 있는 경우"에만 비례환불 → 사람 판단).

### 관리자 (AdminGuard)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/admin/refunds?orderId=&limit=` | 취소 이력 |
| GET | `/api/admin/refunds/assess/:paymentId` | 취소 전 판정(취소가능액·사용량·비례환불액) |
| POST | `/api/admin/refunds` `{paymentId, amountKRW?, credits?, reason}` | 취소 실행. `amountKRW` 생략=전액, `credits` 생략=취소 비율만큼 회수 |
| POST | `/api/admin/refunds/reconcile` `{paymentId}` | PG 콘솔에서 이미 취소한 건을 우리 쪽에 반영(복구용) |

## 2. 정책 → 코드 매핑 (`public/refund.html`)

| 규정 | 구현 |
|---|---|
| 제2조 ① 청약철회 7일 | `WITHDRAWAL_DAYS = 7` — 셀프 전액환불 조건 |
| 제3조 제공개시분 철회 제한 | `usedSince()` > 0 이면 셀프 환불 차단 |
| 제4조 ① 미사용 전액환불 | `selfRefundable` = 미사용 + 7일 이내 + 잔액 충분 |
| 제4조 ② 부분사용 비례환불 | `prorated.amountKRW = 결제금액 × (미사용 ÷ 총구매)` — 관리자 경로에서만 |
| 제4조 청구 가능기간 12개월 | `CLAIM_DAYS = 365` |
| 제7조 원결제수단 승인취소 | PortOne `POST /payments/{id}/cancel` (카드 승인취소) |

**"사용분"의 정의**: 크레딧은 대체가능(fungible)이라 "이 결제분을 썼는지"를 개별 추적할 수 없다.
그래서 **지급 시점 이후의 모든 차감**을 사용분으로 본다. 이용자에게 불리하지 않은 방향의 근사다
(다른 잔액을 먼저 썼더라도 사용으로 세므로 회사가 유리해지지 않는다).

## 3. 설계에서 중요한 것 (`src/billing/portoneRefund.service.js`)

### ① 크레딧을 **먼저** 회수하고, 그 다음 PG를 취소한다
반대 순서면 취소 성공 직후 회수 전까지의 틈에 사용자가 크레딧을 써버릴 수 있고, 그러면
**돈은 돌려줬는데 재화는 소비된** 상태로 굳어 되돌릴 방법이 없다.
먼저 회수하면 최악이 "PG 취소 실패 → 크레딧 원복"이라 언제나 복구 가능하다.
(생성 과금이 `charge()` → 실패 시 `refund()` 로 도는 것과 같은 방향)

### ② 금액의 진실원본은 우리 DB가 아니라 PortOne
취소 가능액 = PG가 말하는 `amount.paid − amount.cancelled`. 팩 정가로 계산하면 가격표를 고친 뒤
과거 결제를 취소할 때 어긋난다.

### ③ 동시 취소 방지 = 상태 선점
`billing_orders.status` `paid → refunding` 을 **원자적 UPDATE로 선점**한 세션만 진행
(`verifyAndComplete`의 `pending→paid` 선점과 같은 방식). 두 번 눌러도 두 번 취소되지 않는다.
10분 지난 `refunding`은 다시 선점 가능 — 안 그러면 PG 호출 중 프로세스가 죽었을 때 주문이
영원히 갇힌다. 그 사이 앞선 취소가 실제로 성공했다면 `currentCancellableAmount` 검증에서
PortOne이 거절하므로 이중취소로 이어지지 않는다.

### ④ 웹훅으로 **외부 취소**도 따라잡는다
취소는 우리 API 밖에서도 일어난다(PortOne 콘솔, 카드사 강제취소). `handleWebhook`이
`type`에 `cancel`이 들어간 이벤트를 `reconcileFromPg()`로 보내 크레딧을 회수한다.
PG 누적취소액에서 우리가 기록한 분을 뺀 **차액만** 반영하므로 웹훅이 중복 도착해도 두 번 회수되지 않는다.

### ⑤ 추천 커미션도 되돌린다
전액취소면 `affiliate.reverseCommission()`. 환수액의 진실원본은 요율이 아니라 **그때 남긴 원장 행**이라
요율을 나중에 바꿔도 지급했던 만큼만 정확히 되돌아간다. 추천인이 이미 써버렸으면 남은 만큼만
환수하고 부족분은 로그로 남긴다 — 그걸로 구매자의 환불을 붙잡아 둘 수는 없다.

## 4. DB 변경 (`src/db/migrate.js`, 멱등)

```
billing_refunds  -- 취소 이력. 부분취소 가능 → 주문 1건에 여러 행
  order_id, user_id, amount_krw, amount_usd, credits_clawed,
  reason, requester(CUSTOMER|ADMIN), actor_user_id,
  status(requested|succeeded|failed), pg_cancel_id, raw
payments.refunded_usd  -- 취소 누적액(매출 집계 차감용)
payments.refunded_at
```

`payments`는 `UNIQUE(provider, order_id)`라 환불을 마이너스 행으로 넣을 수 없다 → 컬럼으로 쌓는다.
관리자 매출(`admin.repository.revenue()`)은 이제 `amount_usd − refunded_usd` = **순매출**을 본다.

`billing_orders.status`에 `refunding`·`refunded`가 추가된다(VARCHAR(20), DDL 변경 없음).

실패한 취소 행도 남긴다 — 회수했던 크레딧을 되돌린 사실까지 추적돼야 CS가
"왜 크레딧이 들락날락했나"를 설명할 수 있다.

## 5. PortOne 심사 요건 테스트 절차

메일 3번 "실운영 모드 전환 후 결제 및 환불 테스트 진행(필수)".

1. `GET /api/billing/portone/config` → `configured: true` 확인
2. `/billing`에서 pack9(₩15,000) 결제 → 크레딧 충전 확인
3. `GET /api/billing/portone/refund/{paymentId}` → `selfRefundable: true` 확인
4. `POST /api/billing/portone/refund {paymentId}` → 취소
5. 확인: PortOne 콘솔 결제 상태 `CANCELLED` / 크레딧 잔액 원복 / `billing_refunds` 행 `succeeded`
   / 카드 승인취소 문자

⚠️ **실채널 전환 전에 테스트 채널로 먼저 위 5단계를 완주할 것.** 로직 검증에 실제 청구가 필요 없다.

## 6. 남은 것

- **환불 UI 없음** — API만 구현. `/billing`에 결제내역·환불 버튼이 필요하다(별도 작업).
- **구독 중도해지 환불 미구현** — 규정 제5조 3항(일할 계산)은 아직 코드가 없다.
  현재 해지는 "차기 결제 중단"만 한다. 정기결제 실오픈 전에 필요.
- Eximbay(해외 USD) 취소 경로는 여전히 없다 — 이번 작업은 PortOne 전용.
