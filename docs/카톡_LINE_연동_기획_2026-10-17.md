## 3. 카카오톡 흐름
```
친구추가 → 환영 메시지(버튼 3: 제품컷 · 모델컷 · 사용법)
→ 사진 전송 → 오픈빌더 스킬 서버 POST(이미지 CDN URL, 10분 유효)
→ 5초 안에 "접수했어요, 30초쯤 걸려요" 응답(스킬 5초 제한)
→ 서버: 이미지 다운로드 → 생성 잡 큐 → 20~60초
→ 결과 전달: (A) 오픈빌더 콜백(지연응답, 신청 필요·확인 중) / (B) 알림톡 이미지 템플릿(건당 유료, 템플릿 검수 1~3영업일)
→ 결과 메시지 버튼: 다시 만들기 · 다른 메뉴 · 웹에서 더(딥링크 /creation?idx=…)
```
- 식별: 카카오 user key(1:1 식별 전용, 마케팅 발송 금지) ↔ Doppia 섀도 계정. 카카오싱크 연결 시 정식 계정과 병합.
- 승인 일정(겹쳐 진행 1~2주): 채널 개설 즉시 → 비즈니스 채널 심사 1~3영업일(법인: 사업자등록증+대표 본인인증) → 챗봇 즉시 → 콜백 신청 확인 → 알림톡 발신프로필+템플릿 1~3영업일 → 카카오싱크.
- 지킬 것: ① "AI로 제작한 이미지입니다" 문구 고정 ② 타인 얼굴 합성 차단(얼굴 1명·성인·실사 판별은 Face swap 코드 재사용) ③ 광고성 발송 없음(정보성 알림톡만).

## 4. LINE 흐름
```
友だち追加 → 리치 메뉴 3칸(商品ショット · モデルショット · 使い方)
→ 이미지 메시지 → Webhook(message id) → GET /v2/bot/message/{id}/content 로 원본 수신
→ reply token(약 1분 유효)으로 "受け付けました、30秒ほど" 응답
→ 생성 → push message 로 이미지 결과(originalContentUrl/previewImageUrl, HTTPS 필수)
```
- 승인: Official Account 개설 즉시(무심사). 인증 배지(認証済アカウント)는 선택, 심사 1~2주. LINE Login 채널은 즉시.
- 비용: push 메시지 월 쿼터 — Communication 플랜 무료 200통/월 · Light ¥5,000 5,000통 · Standard ¥15,000 30,000통(2026 기준, 개설 때 재확인). 결과 1장 = push 1통.
- 일본어 UI는 이번 주 번역한 ja 사전 그대로 쓴다(메뉴·안내문 키 추가).

## 5. 공통 백엔드(둘을 한 구조로)
```
nest/messenger/   (dev 규칙: 4종세트 · 봉투 · DTO · POST 200)
  kakao.controller  POST /api/messenger/kakao/skill   (오픈빌더 스킬)

src/messenger/
  inbound.js   채널별 페이로드 → {channel, externalId, imageUrl, text, menu}
  session.js   externalId ↔ shoot/generate 계정(섀도) · 마지막 메뉴 기억(30분)
  jobs.js      큐 + 상태(received → generating → sent/failed) · 재시도 1회
  outbound.js  kakao(callback|alimtalk) · line(push) 어댑터 — 결과 URL은 /images 공개 URL(클라우드플레어 봇 차단 주의 → R2 서명 URL 또는 메신저 CDN 업로드)
테이블: messenger_users(channel, external_id, user_id, menu, free_left, linked_at) · messenger_jobs(id, user, channel, menu, source_url, result_urls, status, error)
```
- 생성은 기존 파이프라인 호출: 제품컷 = Lens 공식 3종, 모델컷 = `POST /api/shoot/models/:id/shot`(공식 AI 인물 1명 + 옷 사진은 Outfit 경로).

## 9. 진행 기록 (2026-10-18)
### 9-1. 붙은 것 — LINE 웹훅 v1 (dev 배포, upstream/develop `d5d0e44`)
- 채널: LINE Developers 프로바이더 안에 **Messaging API 채널 "Doppia dev"** 신설(운영 계정 "Doppia @747ywgao" 는 미연결 — 개발자가 prod 승격할 때 키만 바꾼다). 장기 토큰 발급, 웹훅 URL `https://dev.doppia.ai/api/messenger/line/webhook`, Use webhook ON, 인사말·자동응답 OFF(응답은 전부 우리 서버).
- 코드: `nest/messenger/`(controller→service 브리지, `@HttpCode(200)`, 서명 틀리면 401, 키 없으면 503) + `src/messenger/line.service.js`(본체) + `messenger.repository.js` + `messenger_users` 테이블. `nest/main.ts` 에 raw body 캡처(`express.json({verify})`) — 서명 검증(HMAC-SHA256, 채널 시크릿) 때문.
- 결과 이미지는 **R2 서명 URL**로 준다(클라우드플레어가 LINE fetcher 를 막는다, 10-16 Higgsfield 때와 같은 원인).
- **v1 = Doppia Lens 만**(10-18 저녁 결정). 처음엔 Shoot(AI 인물 캐러셀·장면 프리셋·입히기)도 넣었으나 대표 실측에서 제품컷만 돌아 Shoot 경로는 걷어냈다(git `fdfc99c` 이전 커밋에 남아 있음).
  - 사진 → 제품컷 1장(Nano Banana Pro, 공식 Lens 프롬프트) → push. 스타일 칩 5(흰 배경·화장대·손에 든·플랫레이·선물). 칩을 누르면 **마지막 사진으로 바로 다시**(`last_input`). "다시" 칩.
  - 언어 = LINE 프로필 언어(ko/ja/en, 기본 ja).
- 사고: dev 에서 사용자 테스트 중 누드 결과 4장 → **결과 삭제 기능**(DB+로컬+R2) 추가, 전부 지운 것 확인. Lens/Shoot 결과물 가드는 미해결.

### 9-2. 실측·함정
- 친구추가(follow) 이벤트가 안 온 적 있음 — 웹훅이 켜지기 전에 친구추가가 먼저 되면 LINE 은 재전송하지 않는다. 확인법 = 차단→차단 해제. 이벤트 종류는 이제 로그에 남는다(`line event`).
- 안전망: LINE 공식계정 관리자의 **인사말 메시지 ON** 은 웹훅과 무관하게 항상 온다(문구만 맞추면 됨). 미적용.
- 지금 "무료 3장" 안내는 거짓 — free_left 를 세지 않고 섀도 계정의 가입 보너스 1,500크레딧(=제품컷 약 13장)이 한도다. §10 에서 고친다.
- 비용: push 1통 = 결과 1장. Communication 플랜 무료 200통/월.

## 10. 계정 연결 · 결제 (설계, 미구현 — 대표 질문 10-18 "무한 생성 막고 결제 뒤에만 계속")
**결론: 계정 연결은 가능하고, LINE 이 공식 기능으로 제공한다.** 결제는 채팅 안에서 못 받고 웹이 받는다(LINE Pay 는 일본 법인·가맹 심사 별도).

### 10-1. 게이트 규칙
| 단계 | 규칙 |
|---|---|
| 무료 | `free_left` 3 → 성공할 때마다 −1. 섀도 계정엔 가입 보너스 안 줌 |
| 소진 | 생성 안 함. "결제하고 계속하기" 버튼(URL) 하나만. 사진을 보내도 이 버튼만 다시 |
| 연결 뒤 | 묶인 웹 계정 크레딧으로 장당 차감(제품컷 115). 0 이면 다시 버튼 |

### 10-2. 연결 방법 2가지
| | A. LINE 공식 Account Link | B. 우리 토큰 링크 |
|---|---|---|
| 흐름 | `POST /v2/bot/user/{userId}/linkToken`(1회용·10분) → 버튼 URL 에 담아 push → 우리 로그인 → nonce 생성·저장 → `https://access.line.me/dialog/bot/accountLink?linkToken=…&nonce=…` 로 리다이렉트 → LINE 이 **accountLink 웹훅**(result ok/failed, nonce, userId) → nonce 로 웹 계정 찾아 묶기 | 버튼 URL 에 `messenger_users.id` 기반 1회용 토큰 → 웹 로그인/가입 → `POST /api/messenger/link` 로 묶기 |
| 조건 | 친구여야 함 · nonce 10~255자·128bit 난수 · **"언제든 연결 해제 가능" 고지 의무** | 없음 |
| 장점 | LINE 이 본인 확인(토큰을 받은 사용자가 맞는지 검증) | 가장 빠름, LINE Login 채널 불필요 |
| 단점 | 리다이렉트 한 번 더 | 링크를 남에게 넘기면 남 계정에 묶임(1회용·10분 만료로 완화) |
- 권장: **B 로 먼저**(오늘 됨) → 운영 전환 때 A 로 교체(공식 검증 + 해제 UX). 둘 다 LINE Login 채널은 불필요. LINE Login(또는 LIFF 안에서 결제)은 "로그인 한 번 더 편하게" 용도의 v2.
- 묶이면 `messenger_users.user_id` 를 웹 계정으로 바꾸고 LINE 으로 "연결됐어요" push. 섀도 계정은 버린다.

### 10-3. 결제 화면
- 웹 billing 그대로(구독 + 충전). 통화: 엔화 Eximbay / 원화 포트원 KCP.
- LIFF 로 billing 을 띄우면 LINE 을 안 나가고 끝난다(선택).
