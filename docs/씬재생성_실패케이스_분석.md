# Ad Video 씬 재생성(🔄) 실패 케이스 분석 & 대책

작성: 2026-07-11 · 대상: `ugcSceneRedo` → `/ugc/re-render` → `reRender`(redoScenes) 경로

## 배경
- **현상**: 기존 씬 변경(재생성) 요청 시 새 영상 생성이 **간헐적으로만 성공**. 실패해도 잡은 `status='succeeded'`(편집가능 상태)로 돌아가 "성공한 것처럼" 보이나 새 씬은 안 만들어짐.
- **목표**: (a) 성공률을 높이고 (b) 기존 씬 + 새 씬을 둘 다 보여주고 선택 가능하게.
  - (b)는 이미 `versions[]`/`activeVersion` 비파괴 버전 기능으로 구현돼 있음 — **단 재생성이 성공했을 때만**. 즉 핵심은 (a) 성공률.

## 파이프라인 단계
```
ugcSceneRedo → chargeGeneration(과금) → [씬별]
  ① refineScene (Claude, 지시 있을 때)
  ② nanoBanana.generate (Gemini 이미지)
  ③ Kling submit + pollUntilDone (모션, 최대 10분)
  ④ persistSceneClips (Kling http 다운로드 + R2 업로드)
  ⑤ versions[]에 추가(비파괴)
→ assemble (ffmpeg 재조립) → updateJob(succeeded)
실패 시 → charge.refund() + failRerender(잡을 succeeded+error로 복구)
```

## 대책 (우선순위)

### 🥇 1순위 — 이미지·모션 생성 재시도(backoff) 추가
- **대상**: F1, F2, F5, F7 (일시적 실패 — 간헐 실패의 주원인)
- **방법**: `nanoBanana.generate`·`kling.submit`/`poll`에 지수 백오프 재시도(2~3회). 429·5xx·타임아웃·"no image"·moderation(1회)만 재시도, 영구오류(401/403/크레딧)는 즉시 실패.
- **효과**: 간헐 실패 대부분 흡수 → 성공률 급상승. **가장 임팩트 큼.**

### 🥈 2순위 — 실패 사유 구분 + 명확한 UI
- **대상**: F3, F8(크레딧), F2/F7(moderation), 일시오류
- **방법**: 에러를 분류(일시/정책/크레딧/영구)해 유저에 다른 메시지 + **재시도 버튼**. 지금은 "Scene could not be re-generated" 뭉뚱그림.
- **효과**: "성공한 것처럼 보임" 혼란 제거. 유저가 재시도/문구수정 판단 가능.

### 🥉 3순위 — 클립 즉시 다운로드 재시도(F10)
- Kling URL 만료 전 확실히 로컬+R2 저장. 실패 시 재시도 후에도 안 되면 명확 경고.

### 유지(이미 완화됨)
- F4·F12(R2 백필) · F11(cleanup cron) · F13(RAM 4GB) · F14(reaper) · F15(chainRun) · F16(과금 가드)

### 인프라 모니터링(별도)
- F3(Gemini 선불) · F8(Kling 크레딧) — 잔액 소진 알림. 코드 아닌 운영 이슈.
