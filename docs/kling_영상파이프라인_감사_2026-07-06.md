## 근본 원인(코드 확정)

1. **폴러 엔드포인트 버그** — Kling은 조회도 `image2video`/`text2video`로 분리(task_id는 제출 엔드포인트로만 조회). 폴러가 항상 image2video로만 조회 → **text2video 잡(소스이미지 없는 Custom·텍스트 릴)은 영영 미완료·12분 타임아웃**. → `됐다 안됐다`. **[수정 완료·배포됨: `8dcb214` pollKlingTask]**

2. **폴러 재진입 없음** — `setInterval`이 15초마다 무조건 발화. finalize(다운로드+오디오 3분 인라인)가 15초를 넘으면 **틱이 겹쳐** 같은 잡 중복 처리·attempts 부풀림·중복 Kling 호출 → 조기 타임아웃/레이스. **[수정: 재진입 가드]**

3. **다운로드/제출 fetch 타임아웃 없음** — `fetch(videoUrl)`(완성영상 다운로드)·Kling 제출 fetch가 무한 대기 가능. 다운로드가 매달리면 폴러 정지, **제출이 Cloudflare 100초 한도(코드 주석 명시)를 넘기면 프록시가 HTML 502** 반환 → 프런트 JSON 파싱 크래시. **[수정: fetchWithTimeout — 제출 45s, 다운로드 120s, 오디오 60s]**

4. **`finalizing` 고아** — 폴러 SELECT는 `processing`만 잡음. 크래시/재배포로 `finalizing`에 멈춘 잡은 **영원히 방치**(사용자 영상 무한 로딩). **[수정: 5분+ 된 finalizing → processing 회수, dup-guard가 중복저장 방지]**

5. **finalize 에러 단계 미구분** — "output failed to save"의 실체(다운로드 실패/FS 쓰기 실패/DB)가 `video_jobs.error`에 뭉뚱그려짐. **[수정: 단계별 라벨 — `video download failed` / `output dir not writable` / `file write failed (FS <code> @ <dir>)`]**

6. **프런트 방어 파싱 부재** — 프록시 HTML 응답 시 `res.json()`이 `Unexpected token '<'`로 크래시. **[수정: studio `sjson()` / creation `ctJson()` — 배포됨]**

7. **재생성 커버 첫 프레임 PNG(수 MB)** — 업로드/제출 지연 → 프록시 타임아웃 유발. **[수정: JPEG 0.85 축소 — 배포됨 `cd2724d`]**

## 인프라/후속(코드로 못 고침 — 개발자 영역)

- **미디어 스토리지**: 신규 영상이 `process.cwd()/tmp/images`(로컬·비영속)에 저장. 멀티인스턴스/재배포 시 404·저장실패 → **오브젝트 스토리지(S3/R2)** 필요. 이번 finalize 라벨로 `video_jobs.error`에 FS 원인(EROFS/EACCES)이 남으면 이게 근본. (기존 [[doppia_media_storage_bug]])
  - ✅ **(2026-07-06) 코드 구현 완료(미배포)** — `src/storage/mediaStore.js` S3 호환 어댑터 + dual-write 훅 + `/images` 로컬우선→S3 302 폴백. env-gated(`MEDIA_S3_BUCKET` 미설정=현행 무변경). 활성화는 버킷 provisioning + .env + 배포 필요 → 정본 `docs/미디어_오브젝트스토리지_설정_2026-07-06.md`.
- **DB 풀 하드닝**: `src/db/client.js` Pool에 `max`·`connectionTimeoutMillis`·`idleTimeoutMillis` 미설정(기본 max=10, 무한대기). 과부하 시 요청이 커넥션 대기로 매달려 CF 100초 초과→502 가능. ⚠️ 이 파일은 로컬 SSL 패치가 있어 이번엔 손대지 않음(푸시 금지 규칙). 개발자가 추가 권장.
- **제출 완전 논블로킹(권장)**: `/video/async`가 요청 안에서 Kling 동기 호출. 이번엔 45초 타임아웃으로 완화. 근본책은 "잡 즉시 생성+jobId 반환 → Kling 제출은 백그라운드(+`queued` 상태 스위퍼)". 별도 리팩터 필요.
- **진단**: 실패 잡 원인은 `SELECT error, count(*) FROM video_jobs WHERE status='failed' AND created_at>now()-interval '3 days' GROUP BY 1`(prod, read-only)로 확정 가능.
