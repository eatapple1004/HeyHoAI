# Product Pack — 상태(state) 차원 + 20컷+ 안전 스케일링 (2026-07-23)

## 왜 (문제)

YSL 립스틱처럼 **한 제품이 여러 모습**인 경우가 있다 — 뚜껑 닫힘(레오파드 케이스·로고가 주인공) vs 뚜껑 열림(누드 총알·컬러가 주인공). 파는 스토리가 아예 다르므로 각각 컷 세트가 필요하다.

그런데 기존 파이프라인은 **"제품 1개 = 정체성 1개 → 대표 레퍼 1장 → 컷 N개"** 구조였다. 급소 2개:

1. **모든 스틸이 `refs[0]` 한 장만 참조** (`pack.service.js` 구 96·105행). 닫힘/열림 사진을 2장 넣어도 레퍼는 첫 장만 쓰여 **전 컷이 한 상태로만** 나왔다. 세트(변형)일 때도 개별 스틸은 첫 변형만 쓰고, 변형들은 로우 합성에만 들어갔다.
2. **컷 개수 천장 ~12.** 플래너가 "8–12컷"을 지시받고, 컷마다 **긴 영어 프롬프트를 통째로** 한 JSON에 담아 뱉는다(max_tokens 8000). 여기서 그냥 "20컷 만들어"로 바꾸면 JSON이 잘려(→파싱 실패→중립 폴백 6컷) **오히려 더 적고 밋밋해진다.** ← 지난 오분류 참사와 같은 truncation 함정.

두 문제의 뿌리가 같다: **상태라는 차원이 없다.**

## 설계

### 1. 상태(state) = 변형(variant)과 별개의 축

- **variants** = 서로 다른 SKU (빨강/파랑, MON/TUE 병) — 기존 축
- **states** = **같은 하나의 제품**을 다르게 보여준 모습 (뚜껑 닫음/열음, 접힘/펼침, 포장/개봉) — 신규 축

v1은 **둘 중 하나**만 (단일 SKU × 상태). 색상변형 × 상태 동시 매트릭스는 후속.

🔑 **상태는 사진에 실제로 보이는 것만.** 안 찍힌 상태는 캐논 레퍼를 구울 수 없다 → classify 프롬프트에서 "attached 사진에서 보이는 것만, 다 같은 상태면 정확히 1개" 로 못박음.

### 2. 스케일링 = 상태별로 플래너를 나눠 호출

"압축 스펙 + 템플릿 전개"도 후보였으나 **플래너의 제품 맞춤 프롬프트(강점)를 희생**한다. 대신:

- 상태마다 `planPack({state})` 를 **따로 호출** → 호출당 출력이 8~10컷로 유지 → **truncation 원천 차단**
- 총 컷 수가 상태 수만큼 **선형 증가** → 2상태 × 8~10 + 합성 = **20컷+가 억지 복제 없이** 나옴
- 단일 상태 제품은 기존 단일 호출(8~12컷) 그대로 — 밋밋한 단품을 20컷으로 억지로 불리지 않는다

### 3. 구현상 비자명한 3가지

| # | 함정 | 대응 |
|---|---|---|
| ① | 두 상태가 똑같이 `pdp_front`를 뱉으면 `assetId`(`kind:cut_key`)가 충돌해 카드가 겹침 | 컷 키를 **상태로 네임스페이스** — `closed__pdp_front` |
| ② | depth는 앞에서 N개를 자르므로, 상태별로 뭉쳐 있으면 "표준 8컷" = 상태A 8 + 상태B 0 | 계획 단계에서 **상태 인터리브**(번갈아 배치) → 슬라이스 로직 변경 0으로 해결 |
| ③ | 재굽기로 레퍼 버전이 쌓이면 합성에 옛 버전까지 들어감(닫힘v1·열림v1·닫힘v2 3장) | `composeRefPaths()` = **상태별 최신 1장씩**만, plan 순서대로 |

# 입력 4형태 기능 감사 + 후속 수정 (같은 날)

목표를 "어떤 제품이든 분석해서 맞는 콘텐츠를 대량·다양하게"로 놓고, 입력 4형태를 **실제로 돌려** 감사했다
(`provider.generate`만 스텁 → bakeOne/genStill의 **실제 프롬프트**를 캡처).

## 감사에서 드러난 결함 2개

### 결함 1 — 세트(여러 개 제품)의 스틸이 한 종만 나왔다 ❌

레퍼는 `red·pink·nude` 3장을 다 굽는데 **스틸 9장 전부가 `red` 하나만** 참조했다. 나머지 변형은 굽는 크레딧만
쓰고 로우 합성에만 들어갔다 — 즉 3종 세트를 넣으면 **빨강 컷 9장 + 라인업 1장**, 핑크·누드 개별 컷은 0장.

상태에서 고친 `refs[0]` 고정 버그가 **변형(SKU) 축에는 그대로 남아 있던 것.**

**수정**: 컷→레퍼 바인딩 필드를 `state` → **`refSku`** 로 일반화(상태든 변형이든 같은 필드)하고,
세트일 때 컷을 변형에 **라운드로빈 배분**한다(`cut1=red, cut2=pink, cut3=nude, cut4=red…`).
> 상태처럼 N배로 뽑지 않는 이유: 변형은 "같은 그림, 색만 다름"이라 N배는 지루한 중복이 된다.
> 컷 수는 유지하고 전 변형이 고루 나오게 하는 쪽이 같은 비용으로 다양성이 높다.

### 결함 2 — "한 단위"가 항상 단품으로 가정됐다 ⚠️

베이크에 실제로 나가던 지시: `ONE single product only (never duplicate).` + negative `two or more products`.
그래서 **귀걸이(한 쌍)** 나 **향수+박스**는 첫 베이크부터 틀렸고, 사용자가 게이트에서 손으로 교정해야 했다.

**수정**: classify가 **`unit`** 을 자동 판별한다 — `single | pair | with_package | group`.
`bakeOne`이 이 값으로 단위 문구를 바꾸고, 개체가 둘 이상이 정상인 경우 이를 막던 negative를 뺀다.
우선순위 = **수동 hint > 자동 unit > 기본 단품** (게이트의 "한 쌍으로" 수동 교정은 그대로 최종 권한).

## 부수 수정

- classify 프롬프트에 **각도 ≠ 상태** 명시 — 같은 구성의 정면/측면/클로즈업을 상태 2개로 오판하던 여지 제거.
- 확인 카드의 상태 1개 안내가 `"예: 뚜껑 연 사진"` 이라 **모든 제품에** 립스틱 표현이 나가던 것 → 중립 문구로.
- 확인 카드 `한 단위` 표시에서 조사 오류(`한 쌍`+`로` = "한 쌍로") → 조사 없이 끊어 쓰기.

## 남은 것 / 알려진 갭

- **「컨셉 추가」(add-cut)는 refSku 미인식** — 라이브러리 컷엔 refSku가 없어 최신 레퍼를 쓴다. v1 허용.
- **상태 × 변형 동시 매트릭스 미지원** (v1은 둘 중 하나).
- **단일 상태·단일 SKU 제품의 천장은 ~12컷** — 20+는 상태나 변형이 있어야 자연스럽다. 억지로 불리려면 컷당 ×N 샘플(별도 기능).
- **B(제품+박스 한 사진)는 classify의 `unit` 판별에 달렸다** — 오판하면 박스가 떨어진다. 게이트에서 `박스와 함께` 로 교정 가능.
- 🔴 **prod 실검증 필요**(로컬은 전부 스텁·목): ①립스틱 2장 → 상태 2개·각자 제 상태 ②귀걸이 1장 → unit=pair 자동 판별 ③세트 → 변형별로 고루
