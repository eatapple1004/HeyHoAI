# 미디어 오브젝트 스토리지 설정 (S3/R2) — 2026-07-06

## 배경
신규 영상/이미지가 `process.cwd()/tmp/images`(로컬·비영속)에만 저장돼 재배포·메모리킬(`max_memory_restart 500M`)·cwd 드리프트 시 라이브에서 **간헐 404**. 근본 처방 = 영속 오브젝트 스토리지.

## 코드 변경(이번 세션, 미배포)
- **신규** `src/storage/mediaStore.js` — S3 호환 어댑터. `isRemote()`(버킷 설정 시만 활성)·`put(name,buf)`·`putFile(absPath)`·`remoteUrl(name)`. 업로드 실패해도 throw 안 함(best-effort).
- `src/config/index.js` — `MEDIA_S3_*` env 추가(전부 optional/default).
- `src/index.js` — `/images/:file` 라우트: **로컬 파일 우선**(과거 파일·Range 지원=영상 seek) → 로컬 없으면 원격 폴백 → 둘 다 없으면 404.

### 서빙 두 모드 (env로 선택)
- **비공개 버킷 + 앱 프록시 스트리밍** (= 2026-06-24 R2 결정과 일치): `MEDIA_S3_PUBLIC_BASE` **미설정**. 앱이 GetObject로 읽어 동일출처로 스트리밍, Range 전달→영상 seek 206 정상. 버킷 공개 불필요·CORS 불요. 단 대역폭이 EC2를 경유.
- **공개 CDN/버킷 + 302 redirect**: `MEDIA_S3_PUBLIC_BASE` **설정**. 로컬 없으면 CDN URL로 302 → 대역폭·지연 오프로드(대규모 트래픽 유리). 버킷/오브젝트가 공개(또는 CDN 서명).
- 쓰기 사이트 dual-write 훅(로컬 write 유지 + best-effort 업로드): `generate.route.js`(스튜디오 이미지·영상), `videoJob.service.js`(잡 영상 finalize), `nanoBanana.provider.js`(캐릭터 이미지), `account.route.js`(발행 이미지·영상 2), `adminRefine.route.js`(정밀화 이미지), `scheduler.js`(BGM 병합 릴 2).
- `package.json` — `@aws-sdk/client-s3` 추가(모듈에서 lazy-require → 로컬 미사용 시 부팅 무영향).

**핵심**: `MEDIA_S3_BUCKET` 미설정이면 전부 로컬 동작(현행 무변경). 프런트·DB·URL 생성부 **무변경**. 완전 가역.

## 활성화 절차 (당신이 할 일)

### A. AWS S3 (권장 — 이미 AWS 서울, 동일 리전 = 저지연·egress 없음)
1. **버킷 생성**: 리전 `ap-northeast-2`, 이름 예 `doppia-media`. 퍼블릭 읽기 필요(아래 둘 중 택1):
   - (간단) 버킷 정책으로 `s3:GetObject` public + `MEDIA_S3_PUBLIC_BASE=https://doppia-media.s3.ap-northeast-2.amazonaws.com`
   - (권장) CloudFront 배포 앞단 + 커스텀 도메인 `cdn.doppia.ai` → `MEDIA_S3_PUBLIC_BASE=https://cdn.doppia.ai`
2. **쓰기 권한**: EC2에 **IAM 인스턴스 프로파일**(Role) 부여 — 액션 `s3:PutObject`, 리소스 `arn:aws:s3:::doppia-media/*`. (키를 .env에 안 넣어도 SDK가 자동 사용 → 가장 안전.)
   - 인스턴스 프로파일이 어려우면 IAM 사용자 액세스키를 `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`로 .env에 넣어도 됨.
3. **.env** (prod):
   ```
   MEDIA_S3_BUCKET=doppia-media
   MEDIA_S3_REGION=ap-northeast-2
   MEDIA_S3_PUBLIC_BASE=https://cdn.doppia.ai        # 또는 s3 퍼블릭 URL
   # 인스턴스 프로파일 미사용 시에만:
   # AWS_ACCESS_KEY_ID=...
   # AWS_SECRET_ACCESS_KEY=...
   ```

### B. Cloudflare R2 (대안 — egress 무료, 새 벤더)
1. R2 버킷 생성 + 퍼블릭 접근(r2.dev 또는 커스텀 도메인) → 그 URL이 `MEDIA_S3_PUBLIC_BASE`.
2. R2 API 토큰 발급 → `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`.
3. **.env**:
   ```
   MEDIA_S3_BUCKET=<r2 버킷명>
   MEDIA_S3_ENDPOINT=https://<account_id>.r2.cloudflarestorage.com
   MEDIA_S3_PUBLIC_BASE=https://<r2 퍼블릭 도메인>
   AWS_ACCESS_KEY_ID=<r2 토큰 id>
   AWS_SECRET_ACCESS_KEY=<r2 토큰 secret>
   ```

### C. 배포
```bash
# prod EC2
cd ~/HeyHoAI && git pull && npm install   # @aws-sdk/client-s3 설치
pm2 restart heyhoai
```
프런트(public/)는 이 변경에 없음 → 재배포 불필요.

### D. 검증
- 새 영상/이미지 1건 생성 → prod 로그 `[MediaStore] uploaded images/<uuid> ...` 확인.
- 버킷에 객체 생성 확인.
- `tmp/images/<그 파일>`을 수동 삭제 후 `/images/<파일>` 요청 → **302 → S3**로 정상 서빙되면 성공(로컬 소실에도 404 안 남).

## 남은 사항
- **과거 파일 백필**: 기존 `tmp/images/*`(현재 로컬에 남은 것)는 자동 업로드 안 됨. 필요 시 일회성 `aws s3 sync tmp/images s3://doppia-media/images/`.
- 로컬 dual-write는 유지되므로 디스크는 계속 참(장기적으로 로컬 write 제거 옵션 고려 가능, 단 kling img2video 로컬읽기·statSync 의존 확인 후).
