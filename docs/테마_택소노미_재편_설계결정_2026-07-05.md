## 1. 결정 (확정)

택소노미는 **3층 매트릭스**다:

```
① 카테고리 (제품군)  = 상단 워크스페이스 스위처   ← "의류 ▾" 전환
     예: 의류 · 주얼리 · 가전 · 식품 …
   ② 콘텐츠타입      = 그 카테고리 전용 메뉴(테마칩)  ← 카테고리마다 다름
        예(의류): 제품컷 · 착용컷 · 룩북 · 원단컷 · 화보 · 영상
        예(주얼리): 제품컷 · 착용컷 · 화보 · 매크로
   ③ 변형(파라미터)  = 콘텐츠타입 안 세부           ← parent_id 중첩(스키마 0)
        예(의류 제품컷): 바닥 · 옷걸이 · 고스트 · 오브제 · 디테일
```

- **① 카테고리 = 컨텍스트(그릇), 스위처 방식**(사용자 확정 (b)): 한 계정이 카테고리를 전환하며 사용(에이전시·멀티카테고리 대응). 상단 칩 줄이 아니라 스위처라, 카테고리가 늘어도 상단 안 붐빔.
- **② 콘텐츠타입 = 카테고리별 상이**(균일 아님): 원단컷=의류 전용, 스펙컷=가전, 플레이팅=식품. 콘텐츠타입은 카테고리 안에서 정의.
- **③ 변형 = 파라미터**: 이미 구현된 제품컷 부모-자식(parent_id) 중첩 그대로.

## 2. 근거 (토의 요약)

- **laongen이 콘텐츠타입-우선인 건 단일 카테고리(의류)라서.** Doppia는 다(多)카테고리라 그대로 못 베낌 — 두 축을 다 감당해야 함.
- **"콘텐츠타입을 전역 상단축"(순수 B)은 깨진다**: 콘텐츠타입이 카테고리별로 다르므로 전역 칩은 합집합이라 같이 늘고 커버리지 불균일.
- **"카테고리를 칩으로"(순수 A)도 늘면 붐빔.** → 카테고리를 **칩이 아닌 컨텍스트(스위처)**로 올려 해결. 늘어나는 축(카테고리)을 상단 네비에서 빼고, 각 카테고리가 자기 콘텐츠타입 메뉴를 정의.
- IA 원칙: 작고 안정적인 축을 네비로, 늘어나는 축을 컨텍스트/하위로.

## 3. 현행 데이터 축 (Phase 0 검증 결과)

축이 이미 존재 → 스키마 대공사 아님:
- `recipes.vertical` (fashion/beauty/jewelry/food/…) = **제품 카테고리**. ✔ 그대로 카테고리 축.
- `recipes.category` (OnModel/Lifestyle/Hero/Macro/Reel/Texture/…) = **콘텐츠타입 성격**이나 **세분·불일치**. → 정규화 필요.
- `macro_group` (Shopping/Influencer) = 최상위 모드(유지 or 재정의).
- 현행 UI: 테마칩 = `vertical`(카테고리) / 카드 라벨 = `category`. → **축을 스왑**: 스위처=vertical, 테마칩=정규화 category.

## 4. 남은 결정거리 (Phase 1에서 확정)

- **콘텐츠타입 표준 목록**(카테고리별): 지금 category 값이 OnModel/Lifestyle/Hero… 로 세분·제각각. 이걸 상위 콘텐츠타입(제품컷/착용컷/룩북/화보/원단컷/영상/…)으로 **정규화 + 카테고리별 적용표** 확정 필요. (제품 결정 — 사용자 주도)
- 초안(검토용):
  | 카테고리 | 콘텐츠타입(안) |
  |---|---|
  | 의류 | 제품컷 · 착용컷(온모델) · 룩북 · 원단컷 · 화보 · 영상 |
  | 주얼리 | 제품컷 · 착용컷 · 화보 · 매크로 · 영상 |
  | 가전 | 제품컷 · 스펙컷 · 언박싱 · 라이프스타일 · 영상 |
  | 식품 | 제품컷 · 플레이팅 · 메뉴컷 · 무드 · 영상 |
  | (공통) | 제품컷 · 화보 · 영상 은 대체로 공통 |
- 카테고리 스위처 UI 위치/형태(상단 드롭다운 vs 탭).
- macro_group(Shopping/Influencer)을 카테고리 축에 어떻게 흡수/공존시킬지.

## 5. 단계별 구현 플랜

**Phase 1 — 콘텐츠타입 택소노미 정의 (문서·데이터, 사용자 협업)**
- 카테고리별 콘텐츠타입 표준 목록 확정(위 초안 → 확정).
- 현행 세분 `category` 값 → 표준 콘텐츠타입 **매핑표** 작성.
- 산출: 이 문서 §4 표 확정 + `docs/콘텐츠타입_매핑.md`.

**Phase 2 — UI 재편 (프론트, 스키마 0)**
- Studio 상단에 **카테고리 스위처**(vertical 전환) 신설.
- 테마칩을 `vertical` → **정규화 콘텐츠타입(category)**으로 전환(renderFilters·themes.js CAT_THEMES 재정의: 카테고리→콘텐츠타입).
- 카드 그리드는 선택 카테고리×콘텐츠타입으로 필터.
- productcut을 "의류 › 제품컷"으로 흡수(현재 top-level productcut 테마 → 의류 카테고리의 제품컷 콘텐츠타입).

**Phase 3 — 템플릿 재태깅 (데이터)**
- 기존 템플릿의 `category`를 표준 콘텐츠타입으로 정규화(시드 일괄 수정 + consolidate/export 재빌드).
- fashion 온모델·룩북·릴스 → 의류의 착용컷·룩북·영상으로 이관.

**Phase 4 — 검증·배포**
- :3002 로컬 검증 → prod migrate(필요 시) + 배포. push 승인제.

**미래(코드 0)**: 새 카테고리(주얼리 등) 추가 = vertical + 콘텐츠타입 정의 + 템플릿 시드. 스위처·중첩·컷 UI 재사용.

## 6. 재사용 (이미 구현됨)
제품컷 부모-자식 중첩(parent_id), 컷 선택 썸네일 UI, 예시 이미지 슬롯(/img/productcut/), 파라미터화 — 전부 그대로. 이번 재편은 주로 **축 스왑(vertical=스위처, category=칩) + category 값 정규화 + 스위처 UI**.

- `public/studio.html` — renderFilters(칩=콘텐츠타입), 상단 카테고리 스위처 신설, setMode/vertical 처리.
