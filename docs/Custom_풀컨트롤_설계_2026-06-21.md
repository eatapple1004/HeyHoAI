# Custom 풀 컨트롤 — 설계 (2026-06-21, branch `feat/launch-scope`)

> 사용자 확정 다음 작업. Custom 모드에 **비율 · 해상도 · 네거티브 프롬프트 · Enhance(LLM)** 추가.
> HOT 파일(`generate.route.js`) 포함 → worktree 격리(`~/HeyHoAI-launch`), surgical 수정, push·배포 사용자 전담.
> design-first: 이 문서 = 진실원본. 구현은 이 매트릭스대로.

## 0. 현황(코드 실측 — 추정 아님)
- `POST /api/generate`는 **provider 레이어를 안 쓰고** 라우트 안에서 Gemini/GPT를 **인라인 호출**. (`src/images/providers/nanoBanana.provider.js`는 별도/미사용 경로.)
- 현재 라우트가 받는 body: `characterId, prompt, model('pro'), count, style, templateName, tool, brandKit` + `referenceImages` 파일.
- 현재 라우트는 **aspectRatio·negativePrompt·imageSize를 전혀 안 보냄.** 인라인 Gemini 호출에 `imageConfig` 자체가 없음 → 세 컨트롤 모두 **신규 배선** 필요.
- Custom UI 생성 호출 = `studio.html:927` JSON POST(파일 아님). body에 필드 추가 = 사소.
- LLM 호출 정본 패턴 = `caption.service.js` (`@anthropic-ai/sdk`, `model: env.CLAUDE_MODEL`, `client.messages.create`). Enhance는 이걸 그대로 미러.
- 크레딧 = `credit.service.js` `COSTS`(caption:1, imageBase, imageModelSurcharge{flash:0,pro:1,...}). Enhance/해상도 비용 여기 추가.

## 1. SDK 실측 제약 (`@google/genai` ImageConfig)
- `aspectRatio` 지원값 = **`1:1, 2:3, 3:2, 3:4, 4:3, 9:16, 16:9, 21:9`** (⚠️ 4:5 미지원 — Imagen 계열 별 타입).
- `imageSize` = **`1K, 2K, 4K`** (미지정 시 1K). **2K/4K는 Nano Banana Pro(gemini-3-pro-image) 기능** — flash(gemini-2.5-flash-image)는 1K 가정.
- GPT 이미지(현재 enabled:false)는 `size`만: 1:1→1024x1024 / 세로→1024x1536 / 가로→1536x1024.

## 2. 백엔드 변경 (`generate.route.js` — surgical 3+1)
### 2-1. 비율 (`req.body.aspectRatio`)
- allowlist = Gemini 지원값. 미지정/비허용 → 미적용(기존 동작).
- Gemini 경로: `config.imageConfig = { aspectRatio }` 주입(현재 imageConfig 없음 → 신규).
- GPT 경로: 비율→size 매핑으로 하드코딩 `1024x1024` 대체.

### 2-2. 해상도 (`req.body.imageSize`)
- allowlist = `1K|2K|4K`. **pro 툴일 때만** 2K↑ 허용, 그 외 1K 강제(flash 보호).
- Gemini 경로: `config.imageConfig.imageSize` 주입.
- ⚠️ **실원가**: 2K/4K는 Nano Banana Pro API 단가↑ 가능. 현재 크레딧은 툴별 정액(해상도 반영X). → **결정 D1 참조.**

### 2-3. 네거티브 (`req.body.negativePrompt`)
- provider 관용 그대로: `finalPrompt += "\n\nAvoid: " + neg` (Gemini·GPT 공통, 둘 다 텍스트 프롬프트라 안전). 길이 캡 500.
- prompt 레코드 tags/metadata에 흔적 저장(선택).

### 2-4. Enhance (신규 `POST /api/generate/enhance` + `enhance.service.js`)
- caption.service 미러: `client.messages.create({ model: env.CLAUDE_MODEL, max_tokens: ~400, system, messages })`.
- system = "짧은 아이디어 → 생생하고 구체적인 이미지 프롬프트(조명·구도·렌즈·무드) 1~3문장, 군더더기/머리말 없이 프롬프트만."
- input `{ prompt, mode? }`. output `{ success, data:{ prompt }, credits }`.
- 크레딧 = **결정 D2 참조.** 안전: 결과는 유저가 검토 후 생성하므로 위험 낮음 → 라이트 블록어 체크만(선택).
- charge 실패 시 caption처럼 try/catch + statusCode 패스스루.

## 8. 이미지/비디오 툴 구분 — Custom 통합 (✅ 사용자 확정 2026-06-21, "풀")
> Custom 툴 픽커를 type별(이미지/비디오)로 분리 + 비디오 툴 선택 시 컨트롤·라우팅 전환. **프론트(studio.html) 전용** — `/api/generate/video/async`·typed registry 기존 재사용, index.js·마이그레이션·theme.css 무관.

### 결정/제약
- 비디오는 **reels 플래그 따라 로컬만**(`window.featureOn('reels')`): 로컬 노출, prod 자동 숨김. **kling enable·실 런칭 노출은 별건(미실행)** — 로컬 배선/검증까지.
- `<optgroup>`/`<option>`은 CSS display:none 비신뢰 → 픽커를 **JS 렌더**(`renderToolPicker`)로 비디오 그룹 조건부 포함.

### 변경 (studio.html)
- `FE_TOOLS` = type 부여 + 비디오(kling) 추가. `curToolType()`·`isVideoGen()`·`curDuration()` 헬퍼.
- `renderToolPicker()`: 이미지 optgroup(항상) + 비디오 optgroup(featureOn('reels')). toolSel 인라인 옵션 제거.
- `syncCustomControls()`: 이미지 툴→비율/해상도/네거티브, 비디오 툴→길이(5/10s). (`syncSizeVisibility` 흡수.)
- 디스패치: `isReel = isVideoGen()` (custom+video 포함) → `generate()`·`updateBar()`·Test1 숨김·`genCost()`.
- `generateReel`: duration = custom video면 `curDuration()` else 5. r=null(템플릿없음)도 동작(prompt=extra, source=subject 레퍼런스).
- `genCost`: custom video → `c.video[dur]`. `saveAsTemplate`: video면 type='reel'.

### 검증 결과 (✅ 로컬 2026-06-21, launch-static :8098 throwaway)
- 픽커 그룹: 로컬 = `Image(nano-banana-pro,nano-banana)` + `Video(kling)`. **prod-sim(`?prod=1`) = Image만**(kling 옵션 없음, featureOn('reels')=false).
- 컨트롤 스왑: 이미지 툴 → 비율/해상도/네거티브 표시·길이 숨김. **Kling 선택 → 길이(10s) 표시·비율/해상도/네거티브 숨김, isVideoGen=true.**
- 라우팅: Custom+Kling generate() → **`/api/generate/video/async` + job 폴링**(이미지 `/api/generate` 아님) 확인.
- 시각 확인 스크린샷 OK(TOOL=Kling · LENGTH=10s).
- node 인라인 JS 문법체크 통과.
- 미검증(서버): 실 Kling 호출(키·enabled 필요) — "활성화"는 별건(미실행).

## 9. 툴별 동적 폼 — 스키마 구동 (✅ 사용자 확정 2026-06-21, Leonardo식)
> §8의 type 단위 분기 → **tool 단위 폼 스키마**로 격상. 각 툴이 자기 controls를 들고 와 스튜디오가 폼을 동적 렌더(Leonardo: 모델마다 폼이 다름). **프론트+레지스트리+엔드포인트**, index.js·마이그레이션·theme.css 무관.

### 정본/엔드포인트
- `src/tools/registry.js`: 툴마다 `controls` 스키마 추가(`aspectRatio[]·imageSize[]·duration[]·negative·…`). `IMG_ASPECTS` 공유. **새 툴 = 한 줄로 폼 생성.**
- **`GET /api/generate/tools`**(generate.route, 우리 소유 → index.js 무터치): `{image:[enabled],video:[전체]}` + 각 `controls`. 노출 규칙=이미지는 registry.enabled, 비디오 그룹은 프론트 reels 플래그.

### 프론트 (studio.html)
- `FE_TOOLS` 하드코딩 제거 → `TOOLS_CACHE`(서버 정본) + `FALLBACK_TOOLS`(오프라인/정적 미러). `loadTools()` 부트 로드(실패=폴백).
- `applyToolSchema()`: 선택 툴 controls로 컨트롤 표시 토글 + 옵션 채움. `renderToolPicker()`=서버 카탈로그 기반. `curSize`·`effModelKey/Label`·applyTryTemplate = toolById 기반.

### 검증 결과 (✅ 로컬 2026-06-21)
- 스키마 구동: **pro** = ratio(7값)+size(1K,2K)+negative, **flash** = ratio+negative(**size 없음**, curSize=1K), **kling** = duration(5,10)만. 툴마다 폼 다름 확인.
- 엔드포인트: 페이로드 정확(node 직접 호출), HTTP **401(인증 게이트, 라우트 마운트됨)** — 인증 스튜디오는 쿠키로 200+카탈로그, 정적/미인증은 FALLBACK 우아한 강등.
- 스크린샷(pro: RATIO 9:16·SIZE 2K) · 인라인 JS 문법 OK.
- 미검증(서버): 인증 세션 200 페이로드 실측 = 배포/로그인 후.

### 확장 시드 (#9 어댑터 웨이브)
- Seedance/Happy Horse 등: registry에 `{controls:{duration,aspectRatio,resolution:['640','960','1440'|'720','1080'],audio:true}}` 한 줄 + (신규 컨트롤 타입은 renderer 케이스 1개) → 폼 자동. 비용=costKey 추가.

## 10. 타입 우선 분리 + 비디오 prod 노출 (✅ 사용자 지시 2026-06-21)
> "이미지/비디오를 사전에 분리(Leonardo식 상단 토글) + prod에도 비디오 켜기."

### 결정
- **노출 정본 = `kling.enabled`(레지스트리)**, `reels` 플래그(릴 템플릿 카드)와 **분리**. → Custom 비디오 툴만 prod 노출, 미완성 릴 템플릿 카드는 계속 숨김(reels=false 유지, flags.js 무수정).
- 픽커 비디오 노출 게이트: `featureOn('reels')` 제거 → **`videoAvailable()=카탈로그에 비디오 툴 존재`**(=enabled).

### 변경
- `registry.js`: `kling.enabled=true`. 엔드포인트 `video`도 `enabledOnly:true`(runway 제외 → kling만).
- `studio.html`: **TYPE 세그(Image|Video)** 신설(`#typeSeg`, `.seg`) — 타입을 먼저 고르고 그 타입 툴만 드롭다운에. `curType()/pickType()/videoAvailable()`. `renderToolPicker`=타입 필터 + Video 버튼은 비디오 툴 있을 때만. `curToolType=curType`, `isVideoGen=curType==='video'`. applyTryTemplate=템플릿 tool 타입으로 pickType.

### 검증 (✅ 로컬 8098)
- TYPE [Image|Video] 노출, videoAvailable=true(폴백/엔드포인트 kling). **Image → 툴=[pro,flash]+비율/해상도/네거티브** / **Video → 툴=[kling]+길이(5/10), 비율/해상도/네거티브 숨김**, 상호 전환 OK. 스크린샷(TYPE Video·TOOL Kling·LENGTH 5s).
- 서버: `node --watch`라 3001/3002 자동 재시작 → 새 레지스트리/엔드포인트 반영. 3001 새 studio.html 서빙 확인(typeSeg 마커). **로그인 후 reload 시 3001에도 Image/Video 노출.**
- 엔드포인트 video=[kling] node 직접 확인. (인증 200 실측은 로그인 후.)

### ⚠️ 배포 주의
- **kling.enabled=true가 prod 배포되면 doppia.ai에도 비디오 툴 노출** → 실제 생성은 **KLING_ACCESS_KEY·KLING_SECRET_KEY 필수**. 키 없으면 Generate가 400("Kling API keys not configured")로 실패(우아하나 UX 나쁨). **키 세팅 전 prod 배포 비권장**, 또는 키 준비 후 배포.

## 11. 보유 툴 실측 capability + 폼 개조 (2026-06-21)
> "현재 보유 툴이 실제로 지원하는 양식 파악 → 그에 맞게 생성란 개조." **라이브 경로 코드 실측**(이론 API 아님).

### 라이브 경로
- 이미지 = `generate.route.js` 인라인(Gemini/GPT). provider 파일 미사용.
- 비디오 = `/api/generate/video/async` → `videoJob.service.submit`. **sync `/video`와 `kling.provider.js`는 스튜디오 미사용**(더 많은 기능 보유하나 dead path).

### 개조 (이번 = 실배선 매칭 + 저비용 확장)
