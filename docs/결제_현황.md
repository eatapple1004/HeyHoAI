
## PG(결제수단) — 전략 (확정 2026-06-11)
> **결제는 Eximbay 준비될 때까지 전면 대기.** Lemon Squeezy 우선 오픈은 **보류**(코드는 폴백으로 보존).
> 즉 지금은 결제 미오픈 상태로 두고, Eximbay 가맹점 심사 통과 후 Eximbay로 오픈한다.

| PG | 단계 | 코드 상태 | 운영 상태 |
|----|------|----------|----------|
| **Eximbay** | **메인 (오픈 목표)** | 준비 완료 (mock 아님) | 🟡 **가맹점 심사 대기** → 통과 시 결제 오픈, 구독은 `comingSoon(501)` |
| Lemon Squeezy | 보류 (폴백 보존) | ✅ 실연동 완료 (checkout/webhook/멱등) | ⏸️ 우선 오픈 안 함 (키 미설정) |
| Stripe | 미사용 | 코드 없음 | 문서에만 언급 |

- **Eximbay 플로우**: `ready()` → fgkey 발급 → 클라이언트 팝업 → `status` 서버알림 → `verify` 위변조검증 → 크레딧 충전.
  - ⚠️ **구독 과금만 webhook 미연동** (심사 통과 후 `subscription.service.activatePlan` 호출 예정).
  - 키 필요: `EXIMBAY_API_KEY`, `EXIMBAY_MID` (config/index.js).
- **Lemon Squeezy**: `POST /checkout` → LS 결제페이지, webhook `order_created` → 충전. 키: `LEMONSQUEEZY_API_KEY/STORE_ID/WEBHOOK_SECRET`.
- 결제 기록 멱등: `payments(provider, order_id)` UNIQUE.

## 완성 vs 미완성
**✅ 완성**
- billing.html / pricing.js UI (프로덕션 수준)
- 가격 단일소스 구조 (`/api/pricing` 폴백)
- Lemon Squeezy 실결제 + webhook 멱등
- Eximbay 결제 준비 코드 (심사만 남음)
- entitlements 권한 정의, costMeter 마진계산 함수

**⚠️ 미완성 (BACKEND_HANDOFF.md 기준)**
1. **구독 결제** — Eximbay 심사 통과 후 webhook→`activatePlan` 연결 (현재 admin만 가능, 일반 사용자는 501)
2. **게이팅 강제** — 권한은 정의만, 서버 generate() 시 강제 검증 코드 부재 (무료 사용자가 Pro기능 접근 가능)
3. **워터마크 정책 강제** — Free 첫1회만 제거 로직 미적용
4. **원가 실데이터** — `costMeter.logCost()` 적재 + studio 통합 미완 (PROVIDER_COSTS 추정값)
5. **프론트 mock** — pause/cancel/자동충전/플랜변경 = `alert`/`notify` mock
6. **402 페이월** — `studio.html` 크레딧부족 alert → 인라인 충전 모달 교체 필요
7. **언어 통일** — 결제 alert 한국어 누수 (`'결제가 완료됐어요!'` 등)

## 즉시 필요한 조치 (우선순위)
> 결제 오픈 자체는 Eximbay 심사 대기로 **보류**. 그 외 준비 작업은 병행 가능.
1. 🔑 **Eximbay 가맹점 심사 통과 → 결제 오픈** (블로커, 외부 일정)
2. 🛡️ **서버 게이팅 강제** → 무료/유료 기능·워터마크 분기 (심사와 무관, 지금 가능)
3. 📊 **costMeter 실원가 적재** → 마진 확인 → 가격 placeholder 확정
4. 🔌 **프론트 mock → 실라우트 연결** (pause/cancel/auto-topup)
5. 🌐 결제 문구 영어 통일
6. ⏸️ Lemon Squeezy는 보류 — 코드/가이드는 보존(필요 시 즉시 폴백 가능)
