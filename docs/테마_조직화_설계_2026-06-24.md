## 0. 한 줄 모델
- **글로벌 테마** = 공유 어휘. Doppia 시드 + 크리에이터가 템플릿에 **다중 태그**. → **Explore 테마별 분류**.
- **개인 스튜디오 테마** = 유저가 자기 스튜디오에서 **기본 테마로 시작 + 커스텀 추가**, 각 테마에 템플릿 **자유 넣다/빼다**. → **개인 큐레이션 = 활성 세트**.
- **보너스**: 테마 멤버십이 "넣다뺐다(in_studio 토글)"를 흡수 — 테마에 넣음=스튜디오 활성 / 모든 테마에서 뺌=비활성. (이전 설계의 `in_studio`·`recipe_hidden` 토글 **불필요·대체**.)

## 1. 핵심 개념 분리 (혼동 금지)
| | 글로벌 테마 | 개인 스튜디오 테마 |
|---|---|---|
| 소유 | Doppia(시드) + (후속) 커뮤니티 | 각 유저 |
| 누가 멤버십 정함 | **크리에이터**(자기 템플릿 다중 태그) | **유저**(자기 선반 큐레이션) |
| 쓰임 | Explore 분류 · 개인 스튜디오 첫 시드 | 스튜디오 picker 구성 · 활성 세트 |
| 가시성 | 공유 | 사적 |

"테마"는 **단일·유연·다중멤버십 차원**으로 둔다(주체/샷/산업의 경직된 3축 위계를 강요하지 않음). 기본 시드는 산업/토픽 중심(beauty·fashion…)으로 시작하고, 필요 시 People/UGC 등도 테마로 시드. → 미결 D1.

## 2. 데이터 모델

```sql
-- ① 글로벌 테마 (공유 어휘)
CREATE TABLE IF NOT EXISTS themes (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  slug        text UNIQUE NOT NULL,            -- 'beauty','fashion'
  name        text NOT NULL,
  is_official boolean NOT NULL DEFAULT true,   -- Doppia 시드 = true
  sort_order  int NOT NULL DEFAULT 0,
  created_at  timestamptz NOT NULL DEFAULT now()
);

-- ② 템플릿 ↔ 글로벌 테마 (크리에이터 다중 태그, M:N) — Explore 분류
CREATE TABLE IF NOT EXISTS template_themes (
  template_id uuid NOT NULL REFERENCES marketplace_templates(id) ON DELETE CASCADE,
  theme_id    uuid NOT NULL REFERENCES themes(id) ON DELETE CASCADE,
  PRIMARY KEY (template_id, theme_id)
);
CREATE INDEX IF NOT EXISTS idx_template_themes_theme ON template_themes(theme_id);

-- ③ 유저 개인 스튜디오 테마 (개인 큐레이션) — 기본 시드 + 커스텀
CREATE TABLE IF NOT EXISTS user_studio_themes (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  name        text NOT NULL,
  sort_order  int NOT NULL DEFAULT 0,
  origin      text NOT NULL DEFAULT 'custom',  -- 'default'(시드) | 'custom'
  seed_slug   text,                            -- default일 때 출처 글로벌 테마 slug(중복시드 방지)
  created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_user_studio_themes_user ON user_studio_themes(user_id, sort_order);

-- ④ 개인 테마 멤버십 (M:N · 내장 레시피 + 보유 마켓 템플릿 둘 다)
CREATE TABLE IF NOT EXISTS user_studio_theme_items (
  user_studio_theme_id uuid NOT NULL REFERENCES user_studio_themes(id) ON DELETE CASCADE,
  user_id     uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  item_type   text NOT NULL,                   -- 'recipe' | 'template'
  item_id     text NOT NULL,                   -- recipe 슬러그 또는 template uuid(text)
  added_at    timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (user_studio_theme_id, item_type, item_id)
);
CREATE INDEX IF NOT EXISTS idx_ustitems_user ON user_studio_theme_items(user_id);
```

**활성 세트 판정** = `user_studio_theme_items`에 그 (user, item)이 존재하면 스튜디오 활성. 빼다 = 해당 행 삭제(모든 테마에서 빠지면 picker에서 사라짐, 보유/소유권은 유지).

**내장 레시피 vs 마켓 템플릿**: 글로벌 태그(`template_themes`)는 마켓 템플릿(UUID)만. 내장 173은 `marketplace_templates`에 없으므로(슬러그) — 내장의 테마는 **`recipes.generated.js`의 `vertical`에서 클라이언트 파생**(시드 동치). 개인 멤버십(`user_studio_theme_items`)은 `item_type`으로 둘 다 수용.

## 3. 세 표면 설계

### A. 크리에이터 — 템플릿 생성 시 다중 테마 태그
- **위치**: `studio.html` Save 모달 + `gallery.html` `ctplModal`(Library Save) + `earnings.html` 편집 모달.
- **변경**: 현재 단일 `category`(Custom/Influencer/Shopping/UGC `<select>`) → **글로벌 테마 다중선택**(칩 토글 또는 multi-select). 최소 1개 권장.
- **백엔드**: `POST/PATCH /api/marketplace/templates` 가 `themeSlugs[]`(또는 ids) 수용 → `themes` 검증 → `template_themes` upsert(기존 삭제 후 재삽입).
- `category`는 단기 호환 위해 컬럼 유지(첫 태그를 mode 매핑에 사용) — 후속 폐기. → 미결 D3.

### B. Explore — 테마별 분류
- **위치**: `explore.html` Templates 탭.
- **UI**: 상단 **테마 칩 행**(All + 시드 테마들) + 기존 가격(Free/Paid)·검색. 칩 선택 시 그 테마 템플릿만.
- **백엔드**: `GET /api/marketplace/templates?theme=<slug>` → `JOIN template_themes tt JOIN themes th ON th.slug=$theme`. 응답에 각 템플릿의 `themes:[slug...]`(칩 표시·필터용) 포함.
- 한 템플릿이 여러 테마에 동시 노출(다중 멤버십). 완전성 주장 없음.

### C. 스튜디오 — 개인 큐레이션
- **위치**: `studio.html` pick-a-template 영역.
- **구성**: 유저의 `user_studio_themes` 순서대로 섹션 → 각 섹션에 그 테마의 멤버 타일(내장+보유 마켓).
- **Manage 모드**: ＋테마 만들기 / 이름·순서 편집 / 삭제 · 각 타일 **＋넣기/－빼기**(테마 간 이동·다중소속). ＋Add more = Explore로(획득) 또는 내장 브라우즈.
- **첫 시드(지연·비침습)**: `GET /studio/themes` 최초 호출에 유저 테마가 0이면 → 글로벌 시드 테마들을 `user_studio_themes(origin='default')`로 생성 + 각 테마에 해당 내장 레시피(vertical 매칭) + 보유 마켓 템플릿(template_themes 매칭)을 `user_studio_theme_items`로 채움. (회원가입 플로우 무수정 — 개발자 소유.)
- **엔드포인트**:
  - `GET  /api/studio/themes` — 내 테마 + 멤버(최초면 시드). 
  - `POST /api/studio/themes {name}` — 커스텀 테마 생성.
  - `PATCH /api/studio/themes/:id {name?,sortOrder?}` · `DELETE /api/studio/themes/:id`.
  - `POST /api/studio/themes/:id/items {itemType,itemId}` — 넣기(마켓이면 보유 검증=template_owns 필요). 
  - `DELETE /api/studio/themes/:id/items/:itemType/:itemId` — 빼기.

## 4. 마이그레이션 · 백필
1. `themes` 시드: **산업/토픽** = beauty·fashion·jewelry·food·coffee·home·tech·pet (= 기존 vertical). + People(인물)·UGC(선택). → 미결 D2.
2. `template_themes` 백필: 
   - **내장 173**: `marketplace_templates`에 없으니 DB 백필 대상 아님 — 클라이언트가 `vertical→theme.slug` 파생. ⚠️ Shopping이 `cat`을 vertical로 덮는 함정 주의(메모리) — raw vertical 키 사용.
   - **기존 유저 템플릿**: `category`(소문자/매핑)→가장 가까운 theme slug 1개로 시드(이후 크리에이터가 편집).
3. `user_studio_*`: 시드 없음(지연 생성, §3-C).
4. **PUBLIC_COLS/응답**: 템플릿 목록·상세 응답에 `themes:[slug]` 추가(서브쿼리 array_agg 또는 별도 조회).
5. 멱등(`IF NOT EXISTS`·`ON CONFLICT DO NOTHING`). 배포 시 `npm run migrate` 필수(신규 4테이블).

## 6. 미결 결정 (구현 전 사용자 확인 — 권장 기본값 표기)
- **D1 테마 차원**: 단일 유연 차원(추천) vs 테마+별도 subject/shot 축. → **단일**(시드에 필요한 만큼 토픽 추가).
