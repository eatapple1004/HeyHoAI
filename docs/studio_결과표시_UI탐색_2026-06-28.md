# 스튜디오 결과표시·레이아웃 UI 탐색 (2026-06-28)

스튜디오에 생성 결과를 어떻게 보여줄지 + 레이아웃을 어떻게 잡을지 탐색한 기록.
**프로토타입은 전부 롤백함**(아래 "결론"). 재사용할 기법·결정만 남긴다.

## 핵심 결정·findings

- **Library만으로 부족한 건 "활성 생성"뿐.** 전체 아카이브 브라우징 = Library(My creations)가 충분. 스튜디오에 *전체 피드*를 깔면 Library 복제 + 클러터 → 과함.
- **스튜디오에 필요한 건 "방금/진행중 생성물"의 즉시·새로고침-안전 표시.** 이유:
  - 생성 중 새로고침/이탈 시 — **이미지**=`/api/generate` 단일 블로킹 POST인데 **abort 처리 없음** → 서버가 끝까지 돌아 `resultRepo.insert`로 **결과 저장됨**(`generate.route.js`). **릴스**=`/video/async` job → 자동 저장.
  - 즉 **결과는 안 날아감(Library에 저장)**, 다만 **스튜디오 UI가 못 되살림** → 바운싱 + "실패한 줄 알고 재생성=이중과금" 위험. 이미지 긴 블로킹은 prod 프록시 타임아웃(~100s)에도 취약.
  - → 스튜디오는 **reload 시 최근 1배치/진행중 job 복구**가 핵심 가치. (견고화는 이미지도 비동기 job 전환)
- **결과 카드 표시 규칙(해자 유지)**: 공식=라벨 / **Custom(template_source 빈값)=프롬프트 노출**(스튜디오=본인만이라 안전) / **템플릿=출처("Template: 〇〇")만, base 프롬프트 절대 X**. 배포 전 백엔드에서도 template일 땐 prompt 미전송으로 굳히기.
- **데이터 소스**: `GET /api/generate/results?limit=&offset=` (resultRepo.findAll = `gr.*` + `p.prompt_text`) → `prompt_text·template_source·template_name·model·width·height·file_path·status` 다 옴. 이미지 URL = `/images/` + `file_path.split('/').pop()` (gallery mapRow와 동일).
- **2-컬럼(좌 입력 레일 + 우 결과 캔버스) 시도 → 폐기**: 템플릿을 모달로 빼면 레일이 굳이 필요 없음(사용자 결론). 세로 스택 유지하되 결과/템플릿 처리만 개선하는 방향이 합리적.
- **AUTO 배지** = origin='auto'(자동민팅). Custom 생성 시 시스템이 자동으로 템플릿화한 "출처" 표시지 "자동 추가"가 아님(추가는 수동 add-to-my-templates).

## 재사용 기법: 템플릿 픽커를 "넓은 모달"로 (검증됨)

스튜디오 "Pick a template" 그리드를 컨트롤 박스/레일로 흡수할 때, 좁은 폭에 그리드를 욱여넣으면 1열로 찌부됨. → **선택기 버튼 + 넓은 중앙 모달**이 정답.

### ⚠️ 결정적 함정 (이거 때문에 한 번 막힘)
`position:fixed`는 **조상에 `transform`이 있으면 viewport가 아니라 그 조상 기준**이 된다. 스튜디오 `.step.fade`(fade-in 애니메이션이 transform 사용)가 그 조상이 되어, fixed 모달이 **레일 폭(344px)에 갇힘**(`inset:0`인데도 width=344).

### 해결
모달을 **열 때 `document.body.appendChild`로 transform 조상 밖으로 이동** → fixed가 viewport 기준 → full폭(예: inner 940px, 그리드 4열).

```js
function toggleTemplatePicker(){
  const p=document.getElementById('tplPanel'); if(!p)return;
  if(p.parentElement!==document.body) document.body.appendChild(p); // ★ transform 조상 탈출
  const open=!p.classList.contains('open');
  p.classList.toggle('open',open);
}
document.addEventListener('click',e=>{ if(e.target&&e.target.id==='tplPanel') toggleTemplatePicker(); }); // 백드롭
document.addEventListener('keydown',e=>{ if(e.key==='Escape'){const p=document.getElementById('tplPanel'); if(p&&p.classList.contains('open')) toggleTemplatePicker();} });
```

```css
#tplPanel{display:none}
#tplPanel.open{display:flex;position:fixed;inset:0;z-index:200;background:rgba(0,0,0,.6);align-items:flex-start;justify-content:center;padding:48px 20px;overflow:auto}
#tplPanelInner{width:min(940px,100%);background:var(--surface);border:1px solid var(--border2);border-radius:16px;padding:18px}
```

```html
<!-- 트리거(버튼) + 모달 래퍼로 filterRow/recipeGrid/premiumWrap을 감쌈 -->
<button onclick="toggleTemplatePicker()">Pick a template ▾</button>
<div id="tplPanel"><div id="tplPanelInner">
  <div id="tplPanelHead"><span>Pick a template</span><button onclick="toggleTemplatePicker()">✕</button></div>
  <div id="filterRow"></div> <div id="recipeGrid"></div> <div id="premiumWrap">…</div>
</div></div>
```

- `renderFilters`/`renderRecipes`는 `#filterRow`/`#recipeGrid`를 **id로** 찾으므로 모달이 body로 이동해도 정상 렌더.
- 그리드는 `recipe-grid`의 `minmax(192px,1fr)`이라 940px 모달에서 자동 4열.

### 결과 피드(참고용 스니펫 — 폐기했지만 규칙은 유효)
```js
const isCustom=!r.template_source; // Custom=프롬프트 / 템플릿=출처
```
